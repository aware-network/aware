# Workspace filesystem bootstrap

## Repository preparation source successor

FS adapter 0.1.1 adds the selected physical preparation owner, with SDK/runtime
0.2.1 bounds. It retains the original exact-root/empty-target Git initialization
algorithm and stripped environment: unborn `main`, no seed commit, staging,
remote or implicit parents. New root/metadata directories are private; existing
directory and parent permissions are preserved. Metadata creation is reserved
no-replace before the original Git invocation, never adopted from a racer.

Retained ancestor/root descriptors establish cooperative topology checks. Git
is not continuously confined; currentness proves observed state, not every
write. Effects are recorded before submission and known application survives
late readback/cleanup failure. Durability is not invented. Confirmed descriptor
cleanup is required for success; an unknown release cannot be upgraded by a later
release. Installed dependency closure and customer onboarding remain separate.

The sections below retain historical publication-bootstrap context; they do not
describe the preparation successor's accepted installed readiness.

This internal 0.0.1 package makes the committed filesystem ports discoverable
for original-writer extraction. Source publication now uses the relocated
original writer through genuine Issue consumption and Workspace-owned
transaction validation. It is not the frozen neutral 0.1.0 successor or a
public consumer candidate. Source tests do not qualify installed publication.

The bootstrap explicitly requires the current Workspace runtime and SDK 0.1
families. That legacy SDK remains Service-coupled; this installation does not
establish whole-package neutrality. The future neutral generation requires
separate extraction, dependency qualification and exact installed proofs.

`FilesystemRepositoryCandidatePort` observes exact requested postimages and
HEAD/ref coordinates. Only the original Workspace runtime issues plans and
only the genuine Issue SDK admits publication work. Importability does not
grant an execution claim or bypass the original Git writer.

The Operator commit module is an alias to this same writer, preserving the
selected governance CLI during semantic caller migration. Issue publication
and closeout source composition now use Issue runtime → Workspace SDK; that
source acceptance does not qualify the installed successor dependencies.

`aware_workspace_fs_adapter.repository_mutation_store` is the original durable
mutation-receipt metadata index moved out of the runtime. Explicit composition
supplies it through the existing `WorkspaceRepositoryMutationResultStore` port.
There is no runtime forwarding alias or fallback construction. The v1 persisted
format and original persistence algorithm are unchanged. Store metadata does
not reconstruct Issue or publication authority.

This is a bounded physical source separation. Other runtime FileSystem, delta
store and Service bodies remain under their existing owners until qualified
extraction; the runtime is not yet wholly IO-free. The successor dependency and
canonical neutral installation gates remain open.

Install through the registered module catalog, canonical manifests and locked
package-manager closure. Do not use a path loader or an unrecorded package
install to activate it. Keep the Environment-selected governance CLI unchanged.
