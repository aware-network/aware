# Aware filesystem agent contract

Template version: `aware.protocol.bootstrap.guidance.v1`.

Use the installed `aware` command and this repository's `aware.protocol.toml`.
Do not substitute a checkout launcher or select authority from service availability.
Run `aware issue --help` for supported operations and exact inputs.

Work through one Issue: record the genuine invoking execution, explicit scope,
problem, objective and acceptance. Observe current records before applying an
operation. Preserve unrelated work and staging; Issue scope is not a file lock.
Use the Issue's supported `commit-workspace` operation for repository publication.
Implementation publication and Issue closeout are separate operations.

Keep Issue-source and Protocol-manifest digests distinct. A stale guard requires
fresh observation and evaluation, not automatic refresh or mutation retry.
Retain requests, attempts, publication references and cleanup/effect evidence
for lawful continuation by another execution. Unknown outcomes stay unknown;
never infer rollback, no effects or safe retry from a refusal.

This initial profile provides filesystem Issue authority only. Goal, Feed,
Specification and Evidence records are unavailable until separately admitted.
Bootstrap creates no Issue, approval, seed commit, staging, remote, user
configuration or resident service. Actor strings are provider-native declarations,
not authenticated actor-action issuance. Use the Issue-root `PROTOCOL.md` named
by the manifest for workflow guidance. Existing guidance is never overwritten.
