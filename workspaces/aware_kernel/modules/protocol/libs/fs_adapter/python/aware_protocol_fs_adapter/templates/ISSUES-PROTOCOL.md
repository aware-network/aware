# Aware filesystem Issue protocol

Template version: `aware.protocol.bootstrap.guidance.v1`.

Use `aware issue --help`, then the supported leaf command's help, for exact inputs.
The Issue record root and path template come from `aware.protocol.toml`; release
packages are selected by the installed candidate, not this customer manifest.

1. Prepare an explicit Issue with problem, objective, acceptance and exact scope.
2. Admit the real execution and move the Issue to In Progress through tooling.
3. Make bounded changes, preserve unrelated work, and run relevant verification.
4. Observe the exact current Issue bytes and use `commit-workspace` preview
   before applying the same scoped publication. Preserve its full receipt.
5. Record resolution and verification, then use supported closeout tooling.
   Closeout does not manufacture semantic acceptance or erase failed effects.

Before a handoff, leave genuinely unfinished work, durable next actions and
publication/effect coordinates. Transfer responsibility through the supported
Issue operation; a new execution must not impersonate its predecessor. Scope
and assignment are not repository locks or authenticated hostile-process identity.

Never hand-edit lifecycle or invent a receipt. Refusals retain known and unknown
effects. Preserve cleanup uncertainty and recovery debt; do not automatically
retry publication, delete published bytes or restore spent authority.
