# Project and Proposed Goal filesystem composition

`aware-project-goal-fs-adapter` packages the ten existing original-owner
provider/composition modules for the bounded create-first customer journey.
It uses neutral Project/Goal contracts, genuine Protocol admission, and the
original Workspace/FileSystem publisher, projection and recovery. It introduces
no writer, issuer, evidence store, evaluator or implicit Issue.

The existing entrances retain their exact imports and class/registry identity:

- `aware_workflow.project_customer.InitialProjectCustomerClient`
- `aware_workflow.goal_customer.InitialGoalCustomerClient`

Only these ten selected namespace-fragment files are shipped; the broad
`aware-workflow` distribution, CLI, Service/View and ontology application are
not dependencies. The broad wheel excludes the same files, preventing duplicate
installed ownership. No sources are forked. The neutral six-module fragment is
owned by `aware-project-runtime`.

The accepted profile remains cooperative, same-execution initial authoring:
one first Project, one Proposed undecomposed Goal and a separately receipted
attachment. Full receipts and partial/uncertain outcomes survive; historical
selection grants no permission, stale sources are not refreshed, and reading
does not repair or redispatch. No authentic Identity or general guarded
installation claim follows. An undecomposed Goal is not eligible.

This package has no public command or entry point. Registrar qualification,
consumer lock selection, a pinned non-editable installed customer journey,
release notices and public activation remain separate gates. The shared
development environment is not changed by building these wheels.
