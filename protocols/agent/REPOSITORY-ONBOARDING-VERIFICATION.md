## Semantic and package boundary

`repository_sdk.prepare_repository` is a new public neutral preparation contract.
The separate SDK and FS adapter add **two** distributions. The CLI composes them
with Protocol scaffold setup; `repository create` and `init --create-repository`
share that operation. It creates no Issue, WorkContext, author configuration,
commit, remote or push. Non-atomic failures retain inspectable state.

The prior 19 non-interface wheel names/hashes are unchanged; the CLI gets a3 and
the two small preparation packages are new. All 33 selected original owner files
keep their existing byte dispositions (30 exact, three export facades).
New preparation sources, complete Apache-2.0 texts and scoped notices are included
and hash-accounted. Existing upstream legal bytes and Goal distribution unchanged.
Published contract 1.0.0 and earlier distribution archives remain byte-preserved.
New setups use 1.1.0; already installed repository instructions are not upgraded.

## External evaluation

[Evaluation v2](../evaluations/README.md) is public and independent of internal
Goal-first v1 records. Installation-only findings can be submitted immediately;
there is no mandatory fabricated Goal, baseline, second execution or timestamp.
U/V/R remain separate. Public consumer source visibility is disclosed separately
from development-checkout visibility. Validation proves accounting, not truth.
No private evaluation repository, client transcript or customer data is shipped.

## Limits and next evidence

New creation supports empty targets with existing parents, not importing arbitrary
non-Git trees, nested/bare repositories or hostile-process filesystem isolation.
Publication needs the customer's real configured Git author. Local actor evidence
remains declared, not authenticated. Goal writers, service bindings and remote
publication are unavailable. Current-epoch rejection in the independent Goal reader
remains unsupported; neither this receipt nor Issue closure accepts a Goal.

This is producer installed evidence, not external client acceptance, a registry
release, cross-host reproducibility or exhaustive privacy/legal certification.
The [scoped Issue](../../docs/issues/2026/10/05/fb-2026-10-05-agent-first-evaluation-repository-onboarding-v0.md)
records the exact public Git delivery and follow-up public-clone replay separately.
