# Alignment protocol — documentary v1

For each approved decision, make these facts explicit:

- Customer objective and acceptance; exact owning Issue reference.
- Decision or observation, author execution, source revision/digest and evidence.
- Uncertainty, unsupported capabilities and next independently bounded work.
- What changed from the previous decision; retain history and conflicting evidence.

CURRENT.md summarizes context; it is not an operational current-Issue pointer.
Never choose work from recency, priority summaries or another execution's memory.
Record consequential decisions in the Issue's append-only history through tooling.
Edit alignment docs only as customer-approved, exactly scoped authored source,
and publish through `aware repository commit`.

Do not put mutable product strategy in AGENTS.md or silently change its selected
authority. A service handover or new contract version needs explicit admission,
not whichever interface happens to be available. Protect private customer context;
public disclosure and remote pushes are separately authorized effects.
