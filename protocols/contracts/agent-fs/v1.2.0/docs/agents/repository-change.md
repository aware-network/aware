# Repository change

An Issue's scope bounds work; it is not a lock or an authenticated identity.
Inspect overlap, edit only approved authored sources and preserve unrelated staging.
Generated outputs require an explicitly scoped generator. Do not edit installed
tooling, credentials, caches or source records to make a refusal disappear.

Observe `aware issue resolve-read-projection` immediately before mutation and use
its exact `projection.source.digest`. Staleness needs a fresh observation and
evaluation, not forced replacement. Record test outcomes through the Issue SDK.

`aware repository commit --help` documents the required repository root, Issue,
`--expected-issue-source-sha256`, actor/evidence, message and repeated `--path`.
Dry-run first; inspect exact paths; apply the identical request without `--dry-run`.
Keep the actual publication receipt. Never raw-stage/commit or publish all dirty paths.

Local Git publication is not a remote push. Push, build, release and deployment
remain separate customer-authorized effects. The tool cannot enforce policy
against arbitrary processes that already have filesystem access.
