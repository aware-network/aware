# Coherence between agents

Aware gives agents a shared way to describe work, admit bounded operations,
publish results and leave evidence for another execution. Issues come first;
Specifications add shared intent and constraints; Goals are a later capability.
This preview does not claim faster agents, conflict-free swarms or a benchmark score.

## Readable guidance and supported tooling

The [Issue](issues/README.md), [repository](repository/README.md) and
[Specification](specification/README.md) descriptions explain the workflow.
[Install once](../README.md) to invoke its qualified operations through `aware`.
The [command sequence](WORKFLOW.md) supplies concrete inputs and boundaries.
Readable guidance is useful without claiming an installed capability or admission.

The Agent client mounts original family registrars through Kernel's command
runtime. Commands call typed SDK operations; the selected filesystem providers
and neutral runtimes retain domain decisions and physical effects. The client
does not copy lifecycle policy, parsing, publication or a writer.

Scope and currentness checks make responsibility explicit, not exclusive.
An Issue is not a directory lock. Concurrent agents must preserve foreign work
and resolve actual conflicting edits. Declared filesystem actors are not
authenticated hostile-process identities. Preview is not write authority.

## Changes and their meaning

Workspace deltas describe observed changes. They do not establish intent,
authorization, meaning or causation by a particular operation. Issue results,
repository publication and filesystem observations remain distinct evidence.
Do not assume every Issue mutation emits a correlated retained Workspace delta.
Observed currentness is not every-write detection or continuous confinement.

## Future bridges remain separate

Language and Meta can interpret file deltas into object configuration and
materialization. Object operations can change configured objects and project
their effects to files. Both routes should use the original Workspace change
mechanisms, with their own interpretation and admission proofs.

An explicitly selected API provider may later expose supported operations through
a local or remote service. Service startup and authority migration are separate
decisions, never an availability fallback. These object and service routes are
direction, not capabilities of this filesystem installation or its prerequisites.

[Initialization](INITIALIZATION.md) makes the filesystem workflow easier to
enter through the original Workspace and Protocol owners.
