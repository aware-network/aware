Status: public-layout proposal for review, not published or selected. The existing
public SPEC entrance remains aware-protocol 0.3.0 / aware-spec 0.2.0. This separately
versioned candidate provides aware-protocol 0.3.1 / aware-spec 0.2.0 with the same

## Explicit separate installation

Only after explicit preparer selection of this exact candidate, use a real Python
3.12 executable and a new environment under an existing parent:

```sh
python3.12 protocols/specification/previews/admit-runtime-v1/install.py \
  --python-executable /usr/bin/python3.12 --venv /tmp/aware-spec-admit-env
/tmp/aware-spec-admit-env/bin/aware-protocol version
/tmp/aware-spec-admit-env/bin/aware-spec --help
```

Never overlay a6, the selected SPEC installation or their wheelhouses. This wrapper
verifies the exact source/notice packet and unchanged accepted payload, retaining
both, then delegates to the existing offline installer. After acquisition, no
network, editable import or Aware development checkout is required. Linux x86-64,
Python 3.12 and Git are the supported target. Existing/dangling environment paths
refuse; parent permissions are not changed. Failed installs can retain partial
effects and evidence; rollback is not claimed.

Supported interfaces are aware-protocol (admit, setup-specification) and aware-spec
(observe, iteration-identity). The 27-package closure includes no agent/Issue CLI,
Goal, Service/API, ontology/ORM or Experience runtime. aware-command-runtime 0.1.1
has zero runtime dependencies and no entrypoints. Its command labels do not enforce
SDK binding, authenticate actors, select providers or authorize domain operations.

## Inputs, ownership and limits

The preparer supplies the customer-approved outcome, exact Git root, genuine
harness execution, separately selected a6 Issue client and fresh Issue/manifest
byte digests. Preview is non-authorizing; setup apply requires explicit --apply
and fresh Issue-owned admission covering the manifest and all directory effects.
Preserve full results/refusals, including applied/unknown effects; publication and
closeout are separate operations. Setup creates only directories and the binding.
It does not stage, commit, approve, close, dispatch or push.

Reading requires independently qualified existing SPEC documents and exact request
coordinates. New customers without them stop after setup. SPEC authoring/import,
approved iterations, durable binding and protected SPEC publication are unavailable.
No manual authority creation is a substitute. Currentness is observed state only;
every-write detection and continuous confinement remain unsupported.
