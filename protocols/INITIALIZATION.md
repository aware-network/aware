# Repository initialization

The installed `aware init` composes Workspace repository preparation followed
by Protocol bootstrap. Read [the exact invocation](../README.md) and
[complete instructions](WORKFLOW.md). Understanding guidance, installing tooling,
preparing Git, configuring operations and starting a service remain separate steps.

For a new repository, preview reports Workspace `outcome=planned` and Protocol
`status=prospective_only`, `completion_verified=false`, `effect=none`. These are
not two admitted plans. Apply obtains fresh Protocol admission after Workspace
preparation. Both owner receipts survive; known creation is not rolled back or
automatically retried after a later refusal.

By default bootstrap prepares Issue directories, `aware.protocol.toml` and
`AGENTS.md`. Workspace does not install protocol guidance. No existing file is
overwritten; there is no seed commit, staging, remote, Issue opening or service
startup. SPEC setup is separately Issue-governed, not implicit in init.

Use the actual harness identity and explicitly choose repository and operation
inputs. Initialization is installed-qualified, not unassisted-onboarding evidence.
Automatic guard discovery remains unproved. Never borrow a6 bootstrap or overlay
an old environment to hide a refusal.
